# 把 Karpathy 的 LLM Wiki 变成个人知识库工作流

我把 Karpathy 的 LLM Wiki 理解成一种方法，而不是一个成熟软件：把 Obsidian 当作知识工作的编辑环境，把 Markdown 当作长期可保存、可版本管理的知识底座，把 LLM 当作协助整理、查询、归纳和改写的维护者。

它解决的问题不是“再多装一个笔记工具”，而是让个人知识库从一堆散落笔记，逐渐变成一个可以被检索、被引用、被更新、被发布的系统。

## 这个方法有什么用

传统笔记很容易停在“收藏”和“摘录”：读过的文章躺在文件夹里，临时想法散在日记里，写作时又要重新搜索、重新理解、重新组织。

LLM Wiki 工作流的重点，是在素材和输出之间增加一个“编译层”。原始材料可以很杂，但经过整理后，会变成更稳定的几类页面：

- source：记录某个来源讲了什么，以及哪些判断来自它。
- concept：沉淀一个概念、模式或原则。
- entity：整理人物、组织、项目、产品等实体信息。
- synthesis：把多个来源和概念合并成更可复用的理解。

这样做之后，知识库不只是存档，而会开始产生复利：后续写文章、做研究、回答问题、准备分享时，可以从已有概念和综合页继续推进，而不是每次从零开始。

## 适合谁

这个模式尤其适合三类人。

第一类是长期学习 AI、编程、产品、写作或某个专业领域的人。你需要不断吸收新信息，也需要保留判断变化的轨迹。

第二类是写作者和内容创作者。你可能平时积累很多材料，但真正写作时需要把材料转成清晰观点、文章结构和可引用的论据。

第三类是希望保留本地控制权的人。Markdown、Git 和静态站点让知识库不完全依赖某个平台，即使工具换了，内容仍然在。

它不太适合只想做轻量待办、临时剪藏，或者完全不愿意维护结构的人。这个方法的收益来自持续整理，前期会比普通收藏稍微费一点力。

## 基本循环

我会把这个工作流拆成五步。

1. 捕获：先把链接、摘录、问题、灵感放进一个临时入口，不急着分类到完美位置。
2. 入库：把有价值的材料整理成带来源的 Markdown 页面，保留出处和上下文。
3. 编译：让 LLM 帮忙抽取概念、实体、主题关系和潜在文章角度，但关键判断仍由人确认。
4. 查询：需要写作或研究时，从已有页面里检索、组合、追问，而不是只向模型抛一个孤立问题。
5. 发布：只有明确适合公开的内容，才进入公开知识花园或文章系统。

这个循环的重点是“来源优先”。LLM 可以帮你提炼，但不应该让它凭空把私人知识库变成一堆没有来处的漂亮段落。对于重要判断，最好能追溯到某篇来源、某条笔记、某次阅读或某个已有草稿。

## Obsidian、GitHub 和 Quartz 怎么配合

Obsidian 适合做本地编辑和知识导航。它的双链、图谱、搜索和插件生态，适合维护 Markdown 笔记，也适合在写作时快速穿梭于相关概念之间。

GitHub 适合做版本管理和备份。个人知识库不是一次性文档，而是长期演化的系统。Git 可以记录一次整理改了什么，也能让你在公开发布前检查差异。

Quartz 适合把经过筛选的 Markdown 发布成公开知识花园。它不是私人库的镜像，而是一个只展示已确认可以公开内容的前台。这样可以同时保留两个边界：私下可以粗糙、探索、保留半成品；公开时则要求可读、可引用、没有私人信息。

三者配合起来，大概是这样的：

- Obsidian 负责日常思考和编辑。
- GitHub 负责版本历史和协作式维护。
- Quartz 负责把精选内容变成可浏览、可链接、可长期访问的公开页面。

## LLM 在这里做什么

LLM 更像知识库维护助手，而不是最终作者。它可以帮助：

- 把长材料压缩成结构化摘要。
- 从来源中抽取概念、实体和主题线索。
- 检查某篇笔记是否缺少来源、定义或边界条件。
- 把零散材料整理成文章提纲。
- 帮忙发现相似笔记、重复观点和可以合并的主题。

但它不应该替代人的判断。特别是当信息涉及事实、评价、趋势或技术状态时，仍然需要回到来源确认。一个好的 LLM Wiki 工作流，不是让模型“更会编”，而是让模型更容易在你的材料范围内工作。

## 私人与公开的边界

个人知识库里天然会有未完成想法、私人计划、草稿、实验记录和上下文碎片。公开知识花园不应该直接暴露这些内容。

比较稳妥的方式，是给公开内容设置显式标记：只有被确认可以公开的 Markdown 页面才会进入发布流程。发布前还要移除私人注释、内部上下文、临时问题和不适合读者看到的操作细节。

这让知识库可以保持两种速度：私人空间允许混乱和试错，公开空间负责沉淀和表达。

## 从最小版本开始

不需要一开始就搭一个复杂系统。最小版本可以只有四件事：

1. 一个本地 Markdown 笔记库。
2. 一个固定的素材入口。
3. 几类稳定页面：来源、概念、主题、文章想法。
4. 一个明确的公开标记，用来区分“可以发布”和“仍然私有”。

等这个循环跑顺之后，再引入自动化脚本、索引、发布构建和更细的页面类型。知识库工作流最怕一开始设计得太精密，最后变成维护结构本身，而不是帮助思考。

## 和本站的关系

本站 Lumen Garden 就建立在这个方法论上：先在本地知识库里持续阅读、整理和写作，再把成熟、可公开、适合长期留存的部分发布出来。

也就是说，Lumen Garden 不是一个从零开始写成的博客集合，而是一个由私人知识库编译出来的公开花园。这里的每一篇方法页、概念页和文章，都尽量保留这种原则：来源清楚、边界清楚、可以继续生长。
